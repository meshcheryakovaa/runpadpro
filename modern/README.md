# Runpad Pro Modern — 0.1.0 Preview

Модульное рабочее пространство для Windows 10/11 x64. **Это предварительная новая реализация**, которую следует сначала проверить на отдельном компьютере. Она не является полным переносом всех функций старого Runpad Pro.

## Скачать и запустить

Откройте [Releases](https://github.com/meshcheryakovaa/runpadpro/releases), включите просмотр предварительных релизов и выберите сборку `0.1.0 Preview`:

| Файл | Назначение |
|---|---|
| `RunpadPro-Setup-0.1.0-win-x64.exe` | Установка клиента в Program Files; нужны права администратора |
| `RunpadPro-Client-win-x64.zip` | Распаковать и запустить `RunpadPro.vbs` |
| `RunpadPro-Server-win-x64.zip` | Отдельный центр управления |
| `RunpadPro-Module-*.zip` | Пакеты отдельных модулей |

.NET Runtime включён в пакеты. Для HTML-фона нужен WebView2 Runtime; если он отсутствует, остальная оболочка продолжает работать. [Установщик WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) доступен также для офлайн-установки.

Оболочка запускает пользовательский агент автоматически. Пункт автозапуска агента в установщике необязателен. Установка сама по себе не меняет рабочий стол Windows и не устанавливает системную службу.

В терминале перейдите в папку установки:

```powershell
cd 'C:\Program Files\RunpadPro'
.\runpad.cmd help
.\runpad.cmd doctor
.\runpad.cmd shell
```

## Что работает

- WPF-оболочка: поиск и запуск приложений, полноэкранный режим, просмотр модулей, настройки.
- HTML-баннер рабочего пространства через WebView2; можно указать свой HTML-файл.
- Пользовательский агент и локальная CLI через защищённый канал Named Pipes.
- Загрузка модулей из папки, отдельный процесс каждого модуля, контроль ошибок и перезапуск.
- Модули мониторинга, HTML-фона и Яндекс Диска; пример собственного DLL-модуля.
- Центр управления: компьютеры по классам, сетка экранов, выбор компьютеров флажками, сообщения, открытие сайтов, передача файлов до 50 МБ.
- Очередь команд с подтверждениями, сроком действия и повторной доставкой после потери связи.
- Windows-служба для выключения, перезагрузки и отмены выключения, включая работу без входа пользователя.
- CLI-обновление готовыми релизами, проверка SHA-256, проверка пакета, откат при неуспешной проверке запуска и ручной откат.
- GitHub Actions: сборка, тесты, упаковка установщика и публикация предварительных релизов.

## Настройка рабочего места

```powershell
.\runpad.cmd config show
.\runpad.cmd config set classroom 'Кабинет 43'
.\runpad.cmd config set refreshMilliseconds 3000
.\runpad.cmd app add 'Visual Studio Code' 'C:\Program Files\Microsoft VS Code\Code.exe'
.\runpad.cmd app remove 'Блокнот'
.\runpad.cmd config set wallpaperFile 'C:\user_data\wallpaper.html'
```

Приложения можно редактировать в `%LOCALAPPDATA%\RunpadPro\config.json`. Закройте и снова откройте оболочку после изменения списка приложений вне интерфейса. Токены скрываются в выводе `config show`.

## Центр управления

На преподавательском компьютере распакуйте сервер. Сгенерируйте токен с помощью клиентской CLI либо PowerShell:

```powershell
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
$env:RUNPAD_ADMIN_TOKEN = -join ($bytes | ForEach-Object { $_.ToString('x2') })
# Сохраните токен в менеджере паролей: он потребуется для подключения панели и регистрации ПК.
.\Runpad.Server.exe
```

Локальная панель: `http://127.0.0.1:7090`. Введите токен в форме. Токен панели хранится в памяти вкладки; сервер не записывает его в базу.

**Для локальной сети требуется HTTPS с доверенным клиентским компьютерам сертификатом.** Не отключайте проверку сертификата. Настройка через Kestrel:

```powershell
$env:ASPNETCORE_URLS = 'https://0.0.0.0:7443'
$env:ASPNETCORE_Kestrel__Certificates__Default__Path = 'C:\RunpadServer\server.pfx'
$env:ASPNETCORE_Kestrel__Certificates__Default__Password = 'пароль-сертификата'
$env:RUNPAD_SERVER_DATA = 'C:\RunpadServer\data'
.\Runpad.Server.exe
```

Используйте имя сервера, соответствующее сертификату, и разрешите выбранный TCP-порт в брандмауэре. По умолчанию сервер слушает только loopback; внешний HTTP отклоняется. Сервер можно запускать как отдельный процесс под выделенной учётной записью или через Планировщик заданий. `runpad server` запускает его в переднем плане, если установлен полный клиент.

На ученическом ПК откройте PowerShell администратором:

```powershell
cd 'C:\Program Files\RunpadPro'
$env:RUNPAD_ADMIN_TOKEN = 'токен-центра-управления'
.\runpad.cmd enroll --server 'https://teacher-pc:7443' --classroom 'Кабинет 43' --machine
Remove-Item Env:RUNPAD_ADMIN_TOKEN
.\runpad.cmd service install
```

`--machine` создаёт настройки подключения для всех пользователей этого ПК. Сервер выдаёт отдельный токен устройства; административный токен в клиентских файлах не сохраняется. Без `--machine` подключается только текущий пользователь. Служба получает настройки подключения при `service install`; после смены сервера переустановите службу.

В обычном сеансе ученика:

```powershell
.\runpad.cmd agent start
.\runpad.cmd config set shareScreens true
```

Скриншоты по умолчанию выключены. Захватывается основной монитор; защищённый рабочий стол Windows и экран входа не захватываются. После блокировки панель показывает отсутствие свежего кадра. Сообщения выводятся оболочкой; если она закрыта, уведомление ожидает её запуска. Выключение/перезагрузка планируются на 30 секунд и могут быть отменены. Файлы сохраняются в `Downloads\RunpadPro`, автоматически не открываются.

Удалить устройство и отозвать его токен можно через `DELETE /api/admin/devices/{id}` с административной авторизацией. Журнал результатов доступен в панели. Данные сервера следует хранить на локальном диске с доступом только оператора сервера; файлы раздачи очищаются администратором из `data/files` после использования.

## Модули

```powershell
.\runpad.cmd module list
.\runpad.cmd module install 'C:\Downloads\RunpadPro-Module-wallpaper.zip'
.\runpad.cmd module disable wallpaper
.\runpad.cmd module enable wallpaper
.\runpad.cmd module update wallpaper --version v0.1.0-preview.1
.\runpad.cmd module invoke monitoring snapshot
```

Здесь и далее `v0.1.0-preview.1` — пример: подставьте **реальный тег** выбранного релиза. Идентификатор модуля можно передать вместо локального пакета: он скачивается из Releases этого репозитория. Без `--version` используется последний стабильный релиз; пока доступны только preview, указывайте тег.

Для ручной установки скопируйте готовую папку в `%LOCALAPPDATA%\RunpadPro\modules\<id>`. Файл `module.ready` добавляйте **последним**, после всех остальных файлов. Агент обнаружит пакет при следующем цикле. Для ручного обновления измените версию в манифесте; CLI сама останавливает старый экземпляр и заменяет пакет.

Модули работают с обычными правами пользователя. Поле `permissions` описывает назначение расширения и не создаёт песочницу. Отдельный процесс отделяет сбой расширения от оболочки; устанавливайте доверенный код. Модули никогда не загружаются в системную службу.

[Как написать модуль](docs/modules.md) · [Архитектура и данные](docs/architecture.md).

## Яндекс Диск

```powershell
.\runpad.cmd agent start
$env:RUNPAD_YANDEX_TOKEN = 'OAuth-токен-Яндекс-Диска'
.\runpad.cmd module secret yandex-disk --env RUNPAD_YANDEX_TOKEN
Remove-Item Env:RUNPAD_YANDEX_TOKEN
.\runpad.cmd module invoke yandex-disk upload
```

Токен шифруется DPAPI текущего пользователя. Раз в пять минут обновляется JSON в `app:/RunpadPro/<имя-ПК>-<идентификатор-пользователя>.json`: имя компьютера, пользователь, время и данные модулей, включая батарею. Полный токен в телеметрию не попадает. Для автономного запуска агент должен запускаться при входе этого пользователя. Это выгрузка телеметрии; двусторонняя синхронизация конфигурации пока не реализована.

## Обновление готовыми пакетами

Из Program Files выполняйте команды в терминале администратора; portable-папке повышение прав не требуется.

```powershell
.\runpad.cmd update --check --version v0.1.0-preview.1
.\runpad.cmd update --version v0.1.0-preview.1
.\runpad.cmd rollback
```

Обновление получает ZIP и SHA-256 только из Releases `meshcheryakovaa/runpadpro`. Распаковка проверяет пути, ссылки, размеры и список файлов; затем отдельный updater останавливает процессы установки, заменяет `app`, проверяет CLI и ранее запущенную службу. Предыдущая версия сохраняется в `previous-app`. Данные пользователей и службы находятся вне `app`. Результат записывается в `update-result.json`.

После обновления снова откройте оболочку обычным ярлыком: updater не запускает пользовательскую оболочку с повышенными правами. В других пользовательских сеансах агент вернётся при следующем входе. SHA-256 проверяет целостность загруженного релиза; Authenticode-подпись издателя и защищённая от отката версия в этом preview не реализованы. Не обновляйте компьютер во время активной учебной работы.

## Разработка и Git

Нужны .NET SDK 10, PowerShell 7 и Windows; для установщика — Inno Setup 6.

```powershell
git clone --branch modern/windows-modular https://github.com/meshcheryakovaa/runpadpro.git
cd runpadpro
git pull --ff-only
.\modern\scripts\build.ps1
.\modern\scripts\package.ps1
.\modern\scripts\deploy-local.ps1 -Destination 'C:\user_data\RunpadPro-Dev'
```

`git pull` обновляет исходники; далее нужны сборка и развёртывание. Исходная система не участвует в новой сборке. Выходные файлы находятся в `modern/artifacts`.

Workflow **Modern Windows build** запускается при push/PR. После успешной сборки ветки `modern/windows-modular` создаётся уникальный предварительный релиз. Git-теги `v*` создают обычные релизы. Перед следующим выпуском измените версию в `Directory.Build.props` и аргументе `package.ps1` workflow; тег должен соответствовать версии пакета.

## Замена рабочего стола

На Enterprise/Education/IoT Enterprise предусмотрен установочный скрипт для штатного Shell Launcher. Используйте отдельную стандартную учётную запись ученика:

```powershell
# PowerShell от администратора; Windows может запросить предварительную перезагрузку.
& 'C:\Program Files\RunpadPro\app\tools\Set-RunpadShell.ps1' -User "$env:COMPUTERNAME\student"
# Возврат Explorer для этого пользователя:
& 'C:\Program Files\RunpadPro\app\tools\Set-RunpadShell.ps1' -User "$env:COMPUTERNAME\student" -Disable
```

Для Pro используйте обычную оболочку и автозапуск. Замена оболочки не ограничивает доступ к Windows: политики запуска приложений и системные ограничения нужно настраивать средствами Windows отдельно. Скрипт Shell Launcher, захват экранов, UAC и сценарии нескольких пользовательских сеансов требуют ручной проверки на целевой редакции Windows.

## Границы предварительной версии

Старые плагины и конфигурация не импортируются. Не перенесены старый Rollback/драйвер восстановления системы, биллинг, перехват клавиатуры, тонкая фильтрация приложений, управление принтерами, удалённое управление мышью/клавиатурой и полная замена панели задач. Фон отображается внутри новой оболочки. Автоматического развёртывания политик Windows и двусторонней облачной синхронизации нет. API модулей пока версии 1 и может развиваться с миграцией.
