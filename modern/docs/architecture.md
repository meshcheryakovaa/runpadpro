# Архитектура

| Проект | Контекст и ответственность |
|---|---|
| Contracts | Версия API, интерфейс модуля и JSON DTO |
| Core | Настройки, каталог, супервизор, IPC, клиент сервера, пакеты |
| Agent | Обычный пользователь: модули, телеметрия, захват основного экрана, пользовательские команды |
| Shell | WPF UI; запускает Agent, отображает приложения/модули/уведомления |
| ModuleHost | Отдельный процесс на DLL-модуль; stdio-протокол |
| Service | LocalSystem, Session 0; фиксированный API питания и системная очередь центра управления |
| Cli | Управление настройками, модулями, подключением, службой и обновлением |
| Updater | Проверка и замена app, сохранение previous-app, health check/откат |
| Server | ASP.NET Core: авторизация, JSON-хранилище, очередь, файлы, веб-панель |

## Потоки данных

Shell/CLI обращаются к агенту через Named Pipes с `CurrentUserOnly`; имя канала включает пользователя, каталог данных и ID сеанса. Агент связывается с модулями через stdin/stdout; никакого порта расширения не открывают. Системный pipe доступен только локальному System и администраторам. UI не выполняется в службе.

Агент и служба сами подключаются к Hub по HTTPS; открывать входящие TCP-порты на учениках не требуется. На сервере отдельный административный токен даёт управление классом, а токен устройства авторизует только маршруты собственного ID. В базе сервера хранятся хеши токенов устройств. Токен ученика не даёт административных прав API.

Команда имеет ID, цель `user`/`system`, срок 5 минут и lease 30 секунд. После выполнения клиент сохраняет квитанцию и отправляет ACK. Потеря ACK приводит к повторной доставке, для которой используется квитанция. Это снижает дублирование, но не гарантирует exactly-once при аварии между выполнением действия и записью квитанции. Результат означает выполнение локального обработчика: например, сообщение поставлено в очередь оболочки, выключение запланировано Windows.

Скриншоты хранятся только в памяти сервера, имеют timestamp и считаются устаревшими через 20 секунд. Автообновление панели и агента настраивается отдельно, не реже 1000 мс. При медленной сети панель не запускает перекрывающиеся запросы. Нативная блокировка Windows скрывает защищённый рабочий стол от агента.

## Хранение

| Путь | Содержимое |
|---|---|
| Program Files/RunpadPro/app | Компоненты и встроенные модули; изменяется установщиком/updater |
| `%LOCALAPPDATA%/RunpadPro` | Настройки, расширения, данные, логи и квитанции пользователя |
| `%PROGRAMDATA%/RunpadProClient` | Неизменяемые обычным пользователем общие настройки подключения; токен только собственного устройства |
| `%PROGRAMDATA%/RunpadPro` | Конфигурация, логи, квитанции службы; доступ System/администраторов |
| `RUNPAD_SERVER_DATA` или server/data | База сервера и раздаваемые файлы |
| previous-app | Предыдущая версия компонентов для отката |

`RUNPAD_DATA` переопределяет папку пользователя для тестов/разработки. Запись JSON атомарна через временный файл и переименование. Это файловое хранилище одной копии сервера; кластеризация и транзакции между несколькими экземплярами не поддерживаются. Резервируйте server/data и пользовательские каталоги. Очистка квитанций и полученных/разданных файлов в preview выполняется администратором.

## Обновления

Репозиторий фиксирован: `meshcheryakovaa/runpadpro`. HTTPS и SHA-256 сверяют целостность релизных ZIP; package.json дополнительно содержит полный список файлов и их хеши. Не допускаются выход за каталог, повторяющиеся имена без учёта регистра, Windows device paths, ссылки и чрезмерный размер. Проверка приложения и работающей службы выполняется после переключения `app`; при ошибке восстанавливается previous-app. Настройки и модульные данные не мигрируют автоматически.

Криптографическая подпись издателя, защищённый каталог расширений с отдельными правами на каждое действие и полноценный policy engine — последующие этапы; текущие ограничения не следует считать средством защиты от пользователя с административными правами.
